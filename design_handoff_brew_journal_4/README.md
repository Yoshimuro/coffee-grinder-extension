# Handoff: Brew Journal — итерация 4 (рецепт-подсказка · правка записей · режимы колеса)

## Overview
Четыре доработки поверх текущего `apps/journal` (main, после BJ-11):

1. **Рецепт-подсказка** — редактируемый план стадий на сетапе заваривания; таймер больше не подгоняет, цели показываются тихо.
2. **Дрип разлочен** — у дрип-пакетов те же настройки рецепта, что у воронки (вес, температура, проливы, редактор стадий).
3. **Правка записей журнала** — паттерн «карандашик»: ✎ в строках журнала/ленты и в шапке записи; правка параметров на месте, переоценка через существующий флоу оценки.
4. **Колесо вкусов: три новых режима** — КАРТА (весь санбёрст, скролл+зум), ПОЛОТНО (гигантская панорама с drag-pan и мини-картой), СПИСОК (плоский список с чипами). Правка узлов (BJ-11) работает во всех режимах.

Плюс: главный экран — **только вариант C**; переключатель вариантов удалён.

## About the Design Files
Файлы в этом бандле — **дизайн-эталон в HTML** (`Brew Journal.dc.html` + `data.js`), интерактивный прототип, а не production-код. Задача — **воспроизвести это поведение и вид в существующем кодбейсе** `apps/journal` (React + Vite + TS, Dexie, токены `tokens.css`) его паттернами: экраны в `ui/screens/*`, чистые функции рядом с экраном + юнит-тесты, строки в `data/strings.ts` (RU/EN поровну), стили классами из токенов. Прототип открывается в браузере с диска — это референс поведения.

## Fidelity
**Hi-fi.** Все размеры, кегли и токены в прототипе — целевые. Новых цветов НЕТ: всё собрано из существующих токенов `tokens.css` (обе темы работают из коробки). Углы прямые, tabular-nums, тач-таргеты ≥48px (видимые элементы меньше — добирать прозрачным `::after`, как принято в `components.css`).

## 1. Рецепт-подсказка (сетап заваривания)

### Блок «РЕЦЕПТ»
位置: после сетки параметров (вес/вода/температура/проливы), перед кнопкой СТАРТ. Экран `Brew.tsx`.

- Заголовок: `РЕЦЕПТ` — micro-label 10/2/500, `--dim`. Справа (только если рецепт правился) ссылка `ВЕРНУТЬ АВТО` — 9px/1.5, `--faint`, подчёркивание 1px `--line-5`.
- Список стадий под хайрлайном `--line-2`; строка: 6px зазоры, `padding: 6px 0`, низ `--line-1`:
  - имя стадии — 10/1.5, обрезается многоточием; **первая строка сохраняет своё имя** (СМАЧИВАНИЕ/НАСТАИВАНИЕ), **все последующие подписываются ПРОЛИВ**;
  - степпер длительности: кнопки 26×30 (рамка `--line-4`, глиф 12px `--text-secondary`), значение 40px, 11px tabular, шаг **±5 с**, минимум 0;
  - степпер воды (только bloom/pour/steep): кнопки 26×30, значение 44px `NN г`, шаг **±10 г**, минимум 0; у стадий без воды — прочерк `—` (10px `--muted`, ширина слота 102px);
  - `×` удалить — 24×30, `--muted`; у единственной видимой строки удаление выключено (цвет `--line-4`, cursor default).
- `+ ПРОЛИВ` — пунктирная строка-приглашение (`--line-5`, 40px, 9.5/1.5 `--dim`); новый пролив `['pour', 30, 50]` вставляется **перед хвостовыми drain**.
- Итог: `итого 3:05 · 250 г` — 9px `--faint`, tabular. Если сумма воды рецепта ≠ полю ВОДА — рядом тихая заметка `в рецепте 240 г из 250` (тот же стиль, НЕ ошибка).

### Правила данных
- Пока рецепт не тронут — он **авто**: пересчитывается из `stagesFor` при каждом изменении параметров.
- Первое изменение материализует копию (`recipe`, флаг `recipeTouched`); дальше параметры сетапа на стадии не влияют.
- Смена пачки, девайса, режима гибрида, «повторить» из записи, новая пачка из сетапа — сбрасывают рецепт в авто.
- **Финальный drain и нулевые отметки (stir/valve с dur=0) в редакторе скрыты** — они автоматические и остаются в плане на таймере.
- СТАРТ и «записать без таймера» используют правленый рецепт, если он есть.

### Таймер — тихая цель (`Timer.tsx`)
- Под elapsed: `рецепт 3:05` (вместо «цель …»).
- Блок стадии: имя как было; ниже — **фактическое время стадии** 14px `--text-secondary` tabular (при паузе `+ 0:05`); ниже — серая строка 10px `--faint`: `рецепт 0:45 · 150 г` (для стадий без цели — пусто; при паузе — `даём стечь`).
- **Убраны**: обратный отсчёт `− 0:12`, овертайм `+ 0:0N`, строка «150 г из 250». Сегменты прогресса остаются (заполнение по рецепту, кап 100%).

## 2. Дрип-пакеты
- ВЕС редактируется (предзаполняется `bean.dose` при выборе дрип-пачки), температура и ПРОЛИВЫ — как у воронки, редактор рецепта работает.
- Запись берёт `brew.dose`, а не фиксированную дозу пачки.
- ПОМОЛ по-прежнему скрыт (молоть нечего), девайс скрыт (пакет и есть девайс).
- Строка `brew_drip_note` → «дрип-пакет: молоть нечего — остальное настраивается, как у воронки».

## 3. Правка записей — паттерн «карандашик»
- **✎ в строках** журнала и ленты главной: квадрат 28×28, рамка `--line-4`, глиф 11px `--text-secondary`, по правому краю строки, `align-self: center`; тап (с `stopPropagation`) открывает запись сразу в режиме правки.
- **✎ в шапке записи** (`Detail.tsx`): 44×40 переключатель; выкл: рамка `--line-4`/`--text-secondary`; вкл: рамка `--line-5`/`--text` (тот же язык, что ПРАВКА у колеса).
- Режим правки:
  - в ячейках сетки параметров под значением появляются −/+ (высота 26, рамка `--line-4`): помол ±0.1 (0–36), вес ±0.5 г (4–60), вода ±10 г (40–900), T° ±1 (60–100). ВРЕМЯ/РЕЖИМ/КЛАПАН — только чтение;
  - заметка → textarea (стиль полей ввода; мин-высота 64);
  - кнопка `ПЕРЕОЦЕНИТЬ — ШКАЛЫ И КОЛЕСО` (ghost 48px, рамка `--line-4`, 10/2) — открывает диагностику с предзаполнением из записи: шкалы, заметка, дескрипторы (с интенсивностями), имя дегустации; ГОТОВО возвращает **назад по стеку** (не на главную).
- Сохранение мгновенное, без кнопки «сохранить» и без диалогов (философия BJ-11). Выход с экрана сбрасывает режим правки.

## 4. Главная — только вариант C
Варианты A/B удалены вместе с переключателем; `homeVariant` больше не существует. Главная: ряд ЗАВАРИТЬ + ⇄, ОЦЕНИТЬ ЧАШКУ, лента журнала (с ✎).

## 5. Колесо: режимы УРОВНИ · КАРТА · ПОЛОТНО · СПИСОК
Ряд чипов-переключателей под шапкой (стиль `Chip`: 8.5/1.2, padding 7×10; активный — рамка+текст `--text`). УРОВНИ — прежний drill-down без изменений. Во всех режимах низ экрана — прежний подвал ВЫБРАНО (теги), а в режиме ПРАВКА — панель правки (см. ниже).

### КАРТА (весь санбёрст, «зум 100%»)
- SVG 820×820 на скроллируемом полотне (`overflow: auto` в обе оси), при входе скролл центрируется.
- Кольца: хаб r≈56 (`--bg`, рамка `--line-4`, подпись ВСЁ 9px `--faint`), категории 64–128, подкатегории 128–212, дескрипторы 212–356.
- Углы: вес узла = число листьев (минимум 1); подкатегории и категории занимают сумму своих листьев; зазор между секторами 0.004 rad.
- Цвета — существующая oklch-схема уровней (категории 0.66/0.72 попеременно; подкатегории 0.60–0.82 внутри категории; листья 0.60–0.84). Швы `--bg` (1.5/1.2/1), выбранный узел — обводка `--text` 2.5.
- Подписи радиальные, `--wheel-ink`, каps: категории 9.5/700, подкатегории 8.5, листья 8 (у листа якорь от внутреннего края кольца, на левой половине — флип на 180° и якорь от внешнего). Точки памяти `--wheel-mark` r2.5 у внешнего края листа.
- Зум: − / NN% / + (кнопки 30×30), диапазон **55–130%**, шаг 15; при смене зума скролл заново центрируется.
- **Тап по любому узлу = выбор** (категория/подкатегория — тоже валидный ответ, как `+ имя` в УРОВНЯХ).

### ПОЛОТНО (панорама «огромная картинка»)
- Тот же санбёрст с коэффициентом **K=3**: 2460×2460, кегли ×2.7 (листья ≈21px), толщины и отступы ×3.
- Контейнер full-bleed под шапкой, `overflow: auto`; на десктопе drag-pan мышью (pointerdown/move/up, курсор grab/grabbing), на таче — нативный скролл. Вход — по центру.
- **Мини-карта**: 76×76, правый нижний угол (12px от краёв), рамка `--line-4`, фон `--bg`, внутри мини-колесо категорий (64px) + рамка видимой области 1px `--text`, обновляется на scroll (двигается/масштабируется пропорционально scrollLeft/Top ÷ scrollWidth/Height).

### СПИСОК (всё сразу, плоско)
- Вертикальный скролл: категория — точка цвета 8px + имя 10/2/700 + счётчик листьев справа (`--muted`); низ секции `--line-2`.
- Подкатегория — 8.5/1.5 caps `--faint` (выбранная — `--text`).
- Дескрипторы — чипы: рамка `--line-4`, 10px, точка цвета вкуса 6px слева; выбранный — рамка цветом вкуса (`colOf(id, 0.8)`), текст `--text`; точка памяти `--wheel-mark` 4px справа в чипе.
- Тап по чипу/подкатегории/категории = выбор (или выбор узла в режиме правки).

### Правка в КАРТА/ПОЛОТНО/СПИСОК
ПРАВКА включена → тап по узлу не выбирает, а **открывает панель узла** в подвале:
- пусто: подсказка `тапни модуль — переименовать, скрыть или добавить внутрь` (10px `--muted`);
- узел: точка цвета 7px + имя 10px; действия ✎ (инлайн-инпут + OK/✕) и × (подтверждение `скрыть?` → ДА/✕) — та же вёрстка, что панель уровня BJ-11;
- у категории/подкатегории — ряд `+ ВНУТРЬ`: инпут + пунктирная кнопка; категория → add-sub, подкатегория → add-desc. У листа ряда нет.
- Мутаторы — существующие из `db/repo/wheel.ts` (`renameWheelNode`, `hideWheelNode`, `addWheelNode`); модель база+оверлей не меняется.
- Подсказки первого входа: при смене режима слой пересчитывается; шаги с анкорами, отсутствующими в текущем режиме, молча пропускаются (правило из `hints.ts` уже это покрывает — важно триггерить resync на смену режима).

## State Management (новое)
- Сетап: `recipe: Stage[] | null`, `recipeTouched: boolean` (стор `brew-store`).
- Запись: `entryEdit: boolean` (экранное состояние Detail); правки пишутся в Dexie сразу.
- Колесо: `wheelMode: 'drill'|'map'|'canvas'|'list'` (переживает уход с экрана — хранить в настройке `wheelMode`, по образцу `lang`), `mapZoom`, `mapSel: string | null` (экранное).

## Строки (добавить в `data/strings.ts`, RU и EN поровну)
`rec_title` РЕЦЕПТ/RECIPE · `rec_auto` ВЕРНУТЬ АВТО/BACK TO AUTO · `+` берёт `t_pour` · итог/заметка — см. прототип (`итого … · в рецепте … из …`) · `brew_drip_note` (новый текст) · `wheel_mode_drill` УРОВНИ/LEVELS · `wheel_mode_map` КАРТА/MAP · `wheel_mode_canvas` ПОЛОТНО/CANVAS · `wheel_mode_list` СПИСОК/LIST · `wheel_map_edit_hint` · `wheel_add_inside` ВНУТРЬ/INSIDE · подпись карты в обычном режиме: `тап — выбрать. категория тоже ответ`.
Таймер: `рецепт` вместо `цель` в двух местах (итог и строка стадии).
