## Задача

Экран добавления пачки (`beanAdd`) неудобен. Пользователь назвал три вещи.

### 1. Две кнопки на полке делают одно и то же

`Shelf.tsx` рисует `СНЯТЬ ПАЧКУ` и `ВПИСАТЬ РУКАМИ`. Обе зовут `add(withCamera)` →
`startAdd(withCamera)` + `go('beanAdd')`. Экран один и тот же, отличается только то,
открыть ли камеру сразу.

**Решение.** Одна кнопка `ДОБАВИТЬ КОФЕ` / `ADD COFFEE`. Камера сама не открывается —
человек жмёт фото-слот внутри формы, когда захочет.

Почему не «ДОБАВИТЬ ЗЕРНО» (первая формулировка пользователя): `ЗЕРНО` в приложении —
это значение поля «ФОРМА» (`form_beans`), одно из трёх рядом с `МОЛОТЫЙ` и
`ДРИП-ПАКЕТ`. Кнопка «добавить зерно» врала бы тому, кто вписывает молотый.
Пользователь согласился на «КОФЕ».

### 2. «Нужно минимум 2 снимка» — оставить 1

**Важная находка: этого требования в коде нет.** Проверка снимков отсутствует
полностью — сохранение блокирует единственное условие `disabled={!roastOk}`, то есть
дата. Пачку можно сохранить вообще без фото. «Два снимка» живут только в тексте
подсказки `bean_photo_hint`.

Значит правка — текстовая, а не логическая.

### 3. Название сделать обязательным

Сейчас поле помечено `· необязательно`, пустое имя подменяется на `Без названия`
(`makeBean`, `shelf-view.ts:146`).

### 4. Дата обжарки — календарь в нашей дизайн-системе

Сейчас это текстовое поле со строгим разбором `DD.MM.YYYY` (`parseDate`,
`bean-format.ts:84`). Пользователь: «человеку надо самому поставить точку, хуе-мое,
заёбно, надо чтобы автоматически проставлялись точки».

- Третий вход на экран — `+ ЗЕРНО` с сетапа заваривания (`Brew.tsx:128`,
  `go('beanAdd')`) — не трогаем, он и так шёл без камеры.

### Фото

- `bean_photo_hint` → про один снимок. Предложение:
  RU `хватит одного снимка — лицо пачки` / EN `one shot is enough — the front of the bag`.
- Проверок не добавлять: фото были и остаются необязательными.
- `slotCount()` в `shelf-view.ts:92` (`Math.max(2, …)`) — это карточка пачки на
  экране `bean`, не форма добавления. Решить отдельно; по умолчанию не трогать.

### Имя

- Условие сохранения: валидная дата **и** `draft.name.trim() !== ''`.
- Снять `· необязательно` с подписи поля.
- Фолбэк `bean_untitled` в `makeBean` **оставить**: импорт чужого zip и старые записи
  могут прийти без имени.

### Дата — поле с автомаской

Поле остаётся текстовым и редактируемым руками. Человек набирает только цифры,
точки подставляются сами:

```
2      → 2
25     → 25.
2507   → 25.07.
25072  → 25.07.2
25072026 → 25.07.2026
```

- Точка вставляется автоматически после дня (2 цифры) и после месяца (2 цифры).
- Backspace ведёт себя естественно: удаление через точку убирает предыдущую цифру,
  не заставляя стирать точку отдельно.
- Всё нецифровое из ввода отбрасывается; длина ограничена 10 символами.
- `inputMode="numeric"` сохранить — цифровая клавиатура уже поднимается верно.

Маску вынести чистой функцией рядом с `parseDate` в `ui/bean-format.ts`, например
`maskDate(raw: string): string`, и покрыть юнит-тестами (набор, вставка, удаление,
вставка из буфера).

### Дата — календарь

Новый компонент `DatePicker` в `apps/journal/src/ui/components/`, в общей системе:
моноширинный шрифт, тёмный фон, заглавные подписи, волосяные линейки — как `Stepper`
и `Chip`. Экспорт через `components/index.ts`.

- Рядом с полем — кнопка открытия календаря.
- **Пикер открывается на уже введённой дате**, если она разбирается; иначе на сегодня.
- Сетка месяца, переключение месяцев назад/вперёд.
- **Будущие даты недоступны**: обжарка в будущем сломала бы возраст и фазу на полке
  (`freshness.ts`). Верхняя граница — сегодня.
- Нижняя граница — год назад.
- Выбор даты подставляет её в поле в `DD.MM.YYYY` и закрывает пикер.

## Окружение: грабли, на которые уже наступили

```sh
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
```

**После правки исходников APK надо пересобрать, иначе проверяешь старый.**

системной «назад» физически отсутствовал в сборке, при этом все тесты были зелёные.

```sh
npm run cap:sync -w @coffee/journal        # должен показать 7 плагинов
cd apps/journal/android && ./gradlew assembleDebug
```

**Эмулятор (headless):**

```sh
SDK=$HOME/Library/Android/sdk
$SDK/emulator/emulator -avd Medium_Phone -no-window -no-audio -no-snapshot \
    -gpu swiftshader_indirect -camera-back virtualscene &
$SDK/platform-tools/adb wait-for-device
$SDK/platform-tools/adb install -r apps/journal/android/app/build/outputs/apk/debug/app-debug.apk
```

Экран 1080×2400. Цикл проверки: `adb exec-out screencap -p > f.png` → посмотреть →
`adb shell input tap X Y`. Данные приложения чистятся
`adb shell pm clear com.kovachar.brewjournal`. Гасить: `adb emu kill`.
SystemUI на этом образе изредка уходит в ANR — закрыть диалог «Подождать» и повторить.

## Открытый вопрос

`slotCount()` (`shelf-view.ts:92`) держит минимум два слота фото на карточке пачки —
эхо старого «минимум два снимка». Раз требование смягчается до одного, стоит
спросить пользователя, менять ли и карточку. По умолчанию не трогать.
