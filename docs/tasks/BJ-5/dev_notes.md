## Что построено

**Три уровня одного кольца.** `wheelItems(path, lang)`: `[]` → 9 категорий,
`[cat]` → её подкатегории, `[cat, sub]` → листья. Тон и цветность на всех
уровнях категорийные, различается только светлота — формулы §8.1 как есть
(D-2): категории `i % 2 ? 0.72 : 0.66`, подкатегории `0.6 + i·0.22/(n−1)`,
листья `0.6 + i·0.24/(n−1)`. Фактический максимум 0.82 и 0.84 выше диапазона,
который называет README, и это осознанно: эталон вида — `offline.html`, а он
нарисован именно этими формулами.

**Геометрия** — числа прототипа: `cx = cy = 175`, `r0 = 74`, `r1 = 170`, зазор
0.016 рад, старт с 12 часов по часовой, `viewBox 0 0 350 350`, рендер 322px.
Дуги строит `arcPath` из `domain/geometry.ts` (BJ-3, уже был).

**Подписи** — на радиусе 124, поворот по оси сектора с доворотом на 180° в
левой половине, кегль 8/9/10 по числу секторов, `#0D0D0B`, капс,
`pointer-events: none`.

**Центральная кнопка** — круг радиусом 65: на корне «ВСЁ» и курсор по
умолчанию, глубже — «↑» и имя текущего уровня, тап уводит на уровень вверх.

**Зум.** Смена `key` контейнера (`path.join('/') || 'root'`) пересоздаёт узел, и
CSS-анимация играет заново: `whzin` (.72 → 1) вглубь, `whzout` (1.36 → 1)
наверх, 320 мс `cubic-bezier(.22,.8,.24,1)`. Направление держит поле `dir`;
крошки и центр ставят −1, тап по сектору +1. Под `prefers-reduced-motion`
анимация выключена — этого в прототипе не было, добавлено как гигиена.

**Крошки** «ВСЁ / Фруктовое / Ягоды» — тап по любой обрезает путь до её уровня.
Кнопка `+ <имя>` пунктиром справа добавляет сам нелистовой id дескриптором
(«остановиться можно на любом уровне», README:59) и исчезает, когда этот
уровень уже в наборе.

**Память** — белые точки радиусом 2.3 на радиусе 161. Множество собирается из
дескрипторов всех `done`-записей; нелистовой сектор отмечается, если внутри
него есть хоть один запомненный лист — через обратные ссылки `DESC.cat`/`sub`.
Никаких счётчиков: только факт.

**Выбранное** — теги внизу: общий `Tag` из BJ-4, рамка `colOf(id, 0.8)`, точки
`colOf(id)`, тап по телу крутит интенсивность 2 → 3 → 1, «×» снимает.

## Интеграция с rate-store

Стор не менялся вообще — его контракт для BJ-5 (шапка `rate-store.ts`)
оказался достаточным ровно в том виде, в каком его оставил BJ-4:

- `picked` читается для тегов внизу, для обводки выбранного листа и для
  `addHereTarget` (кнопка «+ <имя>» молчит, если уровень уже выбран);
- `togglePick(id)` — и по листу, и по кнопке «+ <имя>»: строковый id одинаково
  годится для листа, подкатегории и категории, `nameOf`/`colOf` знают все три;
- `setPickIntensity` / `removePick` — под теги.

Сессию колесо не открывает и не закрывает: оно всегда приходит с диагностики,
которая её и завела. `wheel` уже был в `RATING_SCREENS`, поэтому уход на колесо
и возврат по «ГОТОВО» сессию не сбрасывают — шкалы и заметка на диагностике
переживают заход в колесо, а дескрипторы приезжают обратно тем же составом и с
той же интенсивностью (проверено e2e).

Собственного состояния у экрана два поля: `path` и `dir`. Оба живут в
`useState` и намеренно не в сторе — путь по колесу это не часть оценки, и
возвращаться на диагностику он не должен.

**Отклонений от стора нет, расширять API не понадобилось.**

## Память: чтение из Dexie (D-3)

Прототип пересобирал `_mem` на каждом вызове `wheelSvg()` — журнал лежал у него
в состоянии приложения, и обход был дешевле подписки. Здесь журнал в Dexie,
поэтому память читается живым запросом: `useDoneEntries()` (новый хук в
`repo/entries.ts`, выборка по уже существующему индексу `status`), а свёртка в
множество — чистая `memorySet()` под `useMemo`.

Побочный выигрыш: точки появляются сами, как только запись сохранена, даже если
колесо в этот момент открыто (AC-3).

## Отклонения

- **D-1 (новое, к утверждению).** Фокусная рамка секторов. Сектор — это
  SVG-путь с ролью кнопки, и браузер рисует ему свою синюю рамку по
  прямоугольнику габаритов: на круглом секторе она превращается в коробку
  поперёк колеса (видно на первом же тапе). `outline` погашен, а на
  `:focus-visible` сектор отвечает светлым контуром по самой дуге. В прототипе
  вопроса не было — там сектор не был фокусируемым вовсе.
- **Клавиатура.** Секторам и центру добавлены `role="button"`, `aria-label`,
  `tabIndex` и обработка Enter/Space. Прототип был доступен только пальцу;
  вложить настоящую `<button>` в SVG нельзя, поэтому роль навешена руками.
  `aria-label` листа при отметке памяти дополняется строкой `wheel_mem`
  («уже выбирал») — единственное место, где эта строка звучит.
- **`prefers-reduced-motion`** выключает зум. В прототипе не было.
- **Устойчивость к битому пути.** Неизвестный id в `path` не роняет экран, а
  откатывает его на уровень выше (прототип упал бы на `cat.sub` от `undefined`).
- **Точка памяти нелистового id.** Если человек выбрал саму категорию кнопкой
  «+ Фруктовое», отметка появляется на самой категории, но внутрь не протекает:
  конкретных листьев за таким выбором нет. Это прямое следствие формулы §8.7,
  зафиксировано тестом, чтобы не читалось как баг.

Ничего из требований BJ-5 не пропущено; вне скоупа оставлены мини-колесо
(сделано в BJ-4) и голос-подсказки (BJ-6).

## Замечание по репозиторию

Работа шла в общем рабочем дереве параллельно с соседней задачей: по ходу
прогонов в `settings.ts`, `schema.ts`, `conv/model.ts`, `tokens.css` и части
CSS-файлов появлялись чужие правки (конвертер, мини-фикс батч BJ-4). На момент
сдачи всё сведено: typecheck и оба набора тестов зелёные целиком. Файлы BJ-5
с чужими не пересекаются, кроме `strings.ts` (разные ключи) и
`strings.test.ts` (счётчик, сведён).
