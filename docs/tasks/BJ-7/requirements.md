# Требования — BJ-7: APK + DoD + QA

## Контекст
Финал: DoD из `CLAUDE_CODE_TASK.md` (§Definition of Done, продублирован в спеке §11). Android Studio установлен у пользователя. Часть DoD исполнима только человеком на устройстве — для неё готовится русский QA-чеклист (паттерн task-qa-agent из handbook).

## В скоупе
- Gradle-сборка debug-APK (`assembleDebug`) из `android/`; при доступном эмуляторе — установка и запуск, smoke-прогон.
- Автоматизируемая часть DoD: сборка (DoD-1), цикл в браузере/эмуляторе (DoD-2 частично), экспорт-импорт восстановление (DoD-3 в вебе e2e).
- Пиксельная сверка (DoD-5): скриншоты ключевых экранов приложения vs offline.html, протокол расхождений с вердиктами.
- `docs/tasks/BJ-7/qa_checklist_ru.md`: человеко-исполнимые кейсы для утренней проверки на устройстве (авиарежим, камера, уведомление, keep-awake, голос) — формат: предусловия/шаги/ожидаемо/статус(пусто).
- `docs/tasks/MORNING.md`: итоговый отчёт ночи — что готово, как запустить, допущения на подтверждение, известные хвосты.

## Вне скоупа
Release-подпись, публикация, iOS.

## Критерии приёмки
- AC-1: debug-APK собирается; путь к .apk в отчёте.
- AC-2: при рабочем эмуляторе — приложение стартует, home открывается, цикл проходит; иначе — зафиксированная причина и ручной шаг в QA-чеклисте.
- AC-3: пиксельный протокол с парными скриншотами сохранён в досье.
- AC-4: qa_checklist_ru.md покрывает все пункты DoD, неисполнимые автоматически.
- AC-5: MORNING.md написан.
