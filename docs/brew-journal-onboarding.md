# Brew Journal — подсказки первого входа

Дата: 2026-08-02. Статус: спека под реализацию (код пока не трогаем).
Продолжение `docs/brew-journal-ux.md` §11–12: там перечислено, **где** человек
спотыкается, здесь — **что именно** ему показать, **как** и **где это запомнить**.

---

## 1. Что это такое

Подсказка — затемнение экрана с вырезом вокруг одной зоны и короткой сухой строкой
рядом. Одна зона, одна мысль, одно предложение. Никаких иллюстраций, никаких
«Добро пожаловать!», никакого тура из семи слайдов.

```
┌─────────────────────────────┐
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
│░░░░┌───────────────────┐░░░░│   ← вырез: зона видна как есть,
│░░░░│     ЗАВАРИТЬ      │░░░░│      остальной экран затемнён
│░░░░└───────────────────┘░░░░│
│░░░░                     ░░░░│
│░░░░ Заваривание начина- ░░░░│   ← подпись под вырезом
│░░░░ ется здесь. Нужна   ░░░░│      (или над, если места нет)
│░░░░ пачка на полке.     ░░░░│
│░░░░                     ░░░░│
│░░░░ 1 / 3      ДАЛЬШЕ   ░░░░│   ← счётчик и кнопка
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│
│  ПРОПУСТИТЬ                 │
└─────────────────────────────┘
```

**Цепочка** — 1…3 подсказки одного экрана подряд. Больше трёх не бывает нигде:
четвёртую уже не читают.

## 2. Правила показа

1. **Первый фактический вход на экран**, а не первый запуск приложения. Человек,
   который дошёл до колеса вкусов на третий день, увидит подсказку колеса на третий
   день — тогда, когда она нужна.
2. **После загрузки данных.** Полка отвечает асинхронно; подсветить пустое место, где
   через кадр появится карточка, — хуже, чем не подсветить ничего.
3. **Якорь не найден — шаг пропускается.** Половина полей сетапа скрыта по форме кофе;
   подсказка про клапан гибрида не должна висеть в воздухе. Пропущенный шаг **не**
   помечается показанным — он дождётся своего случая.
4. **Тап где угодно — следующий шаг.** Тап не «проваливается» в подсвеченную кнопку:
   человек читал, а не целился.
5. **Записываем «показано» при закрытии цепочки**, а не при показе. Свернул приложение
   на середине — в следующий раз цепочка начнётся заново.
6. **ПРОПУСТИТЬ** закрывает цепочку текущего экрана и помечает показанными все её шаги.
   Глобальное выключение — переключателем в НАСТРОЙКАХ, а не здесь.
7. **Таймер — исключение.** Там идёт время, и модальное затемнение стоит человеку
   секунд. На таймере подсказка — одна строка внизу, не блокирующая ничего; гаснет по
   тапу или по первому нажатию главной кнопки.
8. **Не мешать делу.** Подсказка не появляется, пока открыта камера, системный выбор
   файла, календарь или панель калибровки.
9. Тёмная и светлая темы обе; тач-таргеты ≥48dp; при `prefers-reduced-motion` вырез
   появляется без анимации.

## 3. Где хранить «уже показано»

**Да, хранить можем, и это дёшево — миграция схемы не нужна.**

Таблица `settings` — это key/value: `SettingsValues` перечисляет ключи, а Dexie видит
одну таблицу с индексом по `key`. Новый ключ = новое поле в интерфейсе, схема остаётся
версии 1 (это прямо записано в шапке `db/schema.ts`).

```ts
// db/schema.ts — в SettingsValues
/** Id показанных подсказок. Реестр append-only, см. docs/brew-journal-onboarding.md. */
hints: string[];
/** Выключатель в настройках: false — не показывать больше ничего. */
hintsOn: boolean;

// db/repo/settings.ts — в DEFAULT_SETTINGS
hints: [],
hintsOn: true,
```

Что из этого следует:

| Вопрос | Ответ |
|---|---|
| Переживёт перезапуск? | да — IndexedDB |
| Переживёт обновление приложения? | да — схема не меняется, старая база просто не имеет ключа, и `readSettings` подставит дефолт |
| Уедет в экспорт? | да — `collectExport` пишет `settings` целиком |
| Ломает ли формат обмена? | нет — `EXPORT_VERSION` не меняется, лишний ключ старый читатель игнорирует |
| Что после импорта архива без ключа? | подсказки покажутся заново, один раз. Считаю это приемлемым: чаще всего импорт — это новый телефон |

**Почему не `localStorage`.** Зеркало в `localStorage` есть у темы, но по конкретной
причине: тему надо знать **до первого кадра**, иначе экран мигнёт. Подсказки нужны
через полсекунды после отрисовки — асинхронного чтения IndexedDB хватает с запасом.
Второе хранилище без нужды — второй источник правды.

**Реестр id — append-only.** Ровно как id дескрипторов колеса: в базе лежат строки, и
переименование id означает, что подсказка вылезет заново у всех, кто её уже видел.
Удалять из реестра можно, переименовывать — нет.

### Сброс и выключение

В НАСТРОЙКАХ — одна строка **ПОДСКАЗКИ** с двумя действиями: выключить (`hintsOn`) и
**показать заново** (`hints: []`). Второе нужнее, чем кажется: человек, который
проскочил подсказку тапом, сейчас не имеет способа её вернуть.

## 4. Реестр подсказок

Формат: `id` — экран — якорь (существующий `data-testid`, где он уже есть) — условие
показа — текст RU / EN.

Тексты сухие и короткие: утверждение, точка. Ни «пожалуйста», ни «давайте», ни
восклицаний.

## 5. Что понадобится в коде (план, не задание)

| Файл | Что | Почему так |
|---|---|---|
| `db/schema.ts` | ключи `hints`, `hintsOn` в `SettingsValues` | key/value — миграция не нужна, версия остаётся 1 |
| `db/repo/settings.ts` | дефолты + `markHint(id)`, `resetHints()`, `useHints()` | запись через транзакцию, как `pushRecent` |
| `data/hints.ts` | реестр: id → экран, ключ строки, порядок, условие | append-only, рядом с `traits.ts` и `wheel.ts` |
| `data/strings.ts` | 34 пары ключей RU/EN | таблица строк общая, иначе EN-интерфейс останется русским |
| `ui/hints/hint-view.ts` | чистая логика: какая цепочка активна, какой шаг, что помечать | тестируется без DOM — по образцу `wheel-view.ts` |
| `ui/hints/Coachmark.tsx` | вырез, подпись, счётчик, «ПРОПУСТИТЬ» | один компонент на все экраны |
| `ui/hints/useHintAnchor.ts` | `ref` → `DOMRect`, пересчёт на скролл и поворот | якорь по `ref`, а не по `querySelector` |
| экраны | по одному `ref` на якорь | там, где `data-testid` уже есть, новый атрибут не нужен |
| `ui/screens/More.tsx` | строка «ПОДСКАЗКИ»: выключить / показать заново | иначе проскочившую подсказку не вернуть |
| `tests/unit/hint-view.test.ts` | порядок, пропуск ненайденного якоря, пометка при закрытии | правила из §2 — правила продукта, проверяются тестом |

Реестр `data/hints.ts` намеренно отдельный файл, а не поле у каждого экрана: порядок,
условия и «показано» — одна модель, и она должна читаться в одном месте.

## 6. Открытые вопросы

1. **Первый запуск.** Показывать цепочку `home` сразу при первом открытии — или дать
   человеку сначала осмотреться и показать её при **втором** заходе на главный?
   Склоняюсь к первому: пустая полка сама по себе непонятна.
2. **Подсказка на таймере.** Согласен ли немодальный вариант, или на таймере подсказок
   не надо вовсе — там и так всё подписано?
3. **`h-shelf-age` и фазы.** Пороги (4 и 21 день) — факт из кода. Показывать их числами
   в подсказке или ограничиться «возраст считается от обжарки»?
4. **Сброс при импорте.** Принимаем, что архив без ключа `hints` вернёт подсказки один
   раз, — или считаем отсутствие ключа за «всё показано»?
5. **EN-тексты** выше — рабочий вариант, не вычитанный носителем.
