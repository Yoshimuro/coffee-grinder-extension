# Brew Journal — подсказки первого входа

Обновлено: 2026-11-04. Статус: **реализовано**, с исправлениями по визуальному исследованию CTA.
Продолжение `docs/brew-journal-ux.md` §11–12: там перечислено, где человек
спотыкается, здесь — что ему показывают, как это устроено и как добавить своё.

## 1. Первый запуск и контекстная помощь

Все служебные подписи в интерфейсе пишутся строчными буквами, без точки в конце.
Пустые экраны объясняют, чего пока нет и что можно сделать дальше. Названия
моделей, пользовательские имена и заметки сохраняют исходное написание.

Если полка пуста, Главный объясняет: «добавь кофе, чтобы записать первое
приготовление». Основное действие — «добавить кофе»; оно открывает форму и
начинает новый черновик. После сохранения пачки кнопка меняется на
«заварить кофе». Пока база загружается, эта кнопка не показывает временное
неподходящее действие. «оценить чашку» стоит второй и имеет такую же заливку,
как первая кнопка. Вторичная «конвертация помола» находится ниже обеих.

На пустом Главном автоматического тура нет. На остальных экранах подсказка —
неблокирующая карточка рядом с отмеченной зоной. У неё серая заливка:
тёмно-серая в тёмной теме и светло-серая в светлой, заголовок «подсказки» и тень.
Зона выделена рамкой и лёгкой серой заливкой. Затемнения и перехвата всего экрана нет,
подсвеченная кнопка/поле получает своё обычное действие.

Для просмотра объяснений есть вторичное действие «следующая подсказка», на
последнем шаге — «закрыть подсказку». Это действие не меняет экран.
«отключить подсказки» выключает их глобально;
вернуть их можно в настройках. Нажатие на пустое место ничего не продвигает.

## 2. Правила показа

1. Подсказка появляется при первом подходящем входе на экран. На Главном
   необходима хотя бы одна пачка; до её создания достаточно встроенного
   объяснения первого шага.
2. Поиск зоны начинается через 450 мс, затем повторяется раз в 700 мс, пока
   данные/элементы не готовы. Контейнер с `data-hints-ready="false"` откладывает
   показ всех своих подсказок.
3. Отсутствующая зона остаётся непоказанной. Идентификаторы append-only,
   поэтому существующие настройки не сбрасываются обновлением.
4. Нажатие на подсвеченный контрол выполняет его действие и закрывает
   подсказку. Следующие подсказки этого экрана не вмешиваются в ввод до нового
   посещения. Нажатие на текст/пустое место не заменяет явное «дальше».
5. Прочитанные шаги записываются по одному. Явная кнопка «следующая» позволяет
   изучить остальные объяснения, не выполняя действие.
6. На таймере подсказок нет. «перейти к стеканию» называет следующую стадию;
   «завершить и сохранить» явно сообщает об автоматическом сохранении.
7. Карточка размещается с учётом измеренной высоты текста и перестраивается
   при изменении размера/прокрутке. Длинная карточка прокручивается внутри.
8. Текст поддерживает RU/EN и обе темы. Читаемые вторичные подписи используют
   `--text-muted` (около 5.8:1), декоративные оттенки сохранены отдельно.
9. Подсказка после сохранения предлагает оценку с Главного. Она не обещает
   неподтверждённое уведомление: в вебе планировщика нет, а на телефоне выдача
   разрешения и планирование могут не состояться.

## 3. Где хранится «уже показано»

В таблице `settings`, двумя ключами. **Миграции схемы не потребовалось**:
`settings` — key/value, новый ключ это новое поле интерфейса, версия Dexie
осталась первой.

```ts
// db/schema.ts → SettingsValues
hints: string[];    // id показанных подсказок
hintsOn: boolean;   // выключатель, по умолчанию true
```

| Вопрос | Ответ |
|---|---|
| Переживёт перезапуск? | да — IndexedDB |
| Переживёт обновление приложения? | да, старая база просто не имеет ключа и получает дефолт |
| Уедет в экспорт? | да, `collectExport` пишет `settings` целиком |
| Ломает ли формат обмена? | нет, `EXPORT_VERSION` прежний, лишний ключ старый читатель игнорирует |
| Импорт архива без ключа? | подсказки покажутся заново, один раз — принято решением |

**Почему не `localStorage`.** Зеркало в `localStorage` есть у темы, но по
конкретной причине: тему надо знать до первого кадра, иначе экран мигнёт.
Подсказка появляется через полсекунды после отрисовки — асинхронного чтения
IndexedDB хватает с запасом, а второе хранилище без нужды это второй источник
правды.

**Реестр id — append-only**, ровно как id дескрипторов колеса: в базе лежат
строки, и переименование id вернёт подсказку всем, кто её уже закрыл. Удалять
можно, переименовывать — нет.

### Управление в НАСТРОЙКАХ

Две строки рядом с языком и темой:

- **ПОДСКАЗКИ** · `по одной при первом входе на экран` — чипы ВКЛ / ВЫКЛ;
- **ПОКАЗАТЬ ЗАНОВО** ↻ — забыть показанное и включить обратно.

Второе нужнее, чем кажется: проскочивший подсказку тапом иначе не может её
вернуть.

## 4. Реестр подсказок

**36 подсказок, 1…4 на экран.** Тексты — в `data/strings.ts` (RU и EN), зоны и
порядок — в `data/hints.ts`. Ниже — что где показывается; текст приведён по-русски.

### ГЛАВНЫЙ (`home`)

| id | Зона | Текст |
|---|---|---|
| `h-home-brew` | кнопка заварить кофе | нажми «заварить кофе», чтобы настроить рецепт и начать приготовление |
| `h-home-taste` | оценить чашку | здесь можно оценить чашку, даже если ты не записывал её приготовление |
| `h-home-conv` | конвертация помола | здесь можно перевести настройку помола с одной кофемолки на другую |
| `h-home-pending` | карточка «оценка ждёт» | ты уже записал это приготовление, но пока не оценил чашку |

### ПОЛКА (`shelf`, `beanAdd`, `bean`)

| id | Зона | Текст |
|---|---|---|
| `h-shelf-add` | добавить кофе | здесь можно добавить кофе на полку |
| `h-add-form` | чипы формы | укажи, какой у тебя кофе, чтобы приложение показало нужные настройки приготовления |
| `h-add-photo` | слоты фото | можешь добавить фото пачки или сохранить кофе без фотографии |
| `h-add-roast` | поле даты | введи дату обжарки с пачки или выбери её в календаре. точки между цифрами появятся сами |
| `h-bean-brews` | секция заваривания | здесь собраны все приготовления с этим кофе |

### ЗАВАРИВАНИЕ (`brew`, `rateLater`)

| id | Зона | Текст |
|---|---|---|
| `h-brew-fields` | блок кофе | настройки зависят от выбранного кофе: то, что уже задано производителем, повторно вводить не нужно |
| `h-brew-device` | блок тип заваривания | выбери, в чём будешь готовить кофе. если ничего не выбрать, приложение составит рецепт для конической воронки |
| `h-brew-grind` | блок помол (только с диапазоном) | под помолом показан диапазон из конвертера. можешь взять его за ориентир или указать свою настройку |
| `h-brew-outputs` | кнопка старт | нажми «старт», если собираешься готовить кофе сейчас. если уже приготовил, выбери «записать без таймера» |
| `h-rate-later` | кнопка позже | приготовление уже записано в журнал. оценить чашку можно сейчас или позже с главного экрана |

Таймер подсказок не имеет — см. правило 6.

### ОЦЕНКА (`diag`, `wheel`)

| id | Зона | Текст |
|---|---|---|
| `h-diag-scales` | первая шкала | оцени кислотность, горечь, тело и сладость от 0 до 10, нажимая на нужные деления |
| `h-diag-wheel` | строка колеса | на колесе можно выбрать оттенки вкуса и добавить их к оценке чашки |
| `h-diag-note` | заметка с микрофоном | надиктуй заметку, и приложение предложит добавить распознанные вкусы к оценке |
| `h-wheel-nav` | кольцо | нажимай на секторы, чтобы уточнять вкус. чтобы вернуться на уровень выше, нажми в центр колеса |
| `h-wheel-here` | кнопка «+ имя» | не обязательно доходить до самого точного названия: можно выбрать вкус на любом уровне |
| `h-wheel-tag` | первый выбранный тег | нажми на выбранный вкус, чтобы изменить его интенсивность, или на крестик, чтобы убрать его |
| `h-wheel-memory` | точка памяти на секторе | точки показывают вкусы, которые ты отмечал в предыдущих записях |

### КОНВЕРТЕР (`conv`)

| id | Зона | Текст |
|---|---|---|
| `h-conv-from` | пикер откуда | здесь можно выбрать кофемолку из каталога. введи бренд, модель или сокращённое название, чтобы её найти |
| `h-conv-band` | полоса под результатом | полученная настройка округлена до деления твоей кофемолки. полоса показывает возможный разброс из-за неточности исходных данных |
| `h-conv-cal` | откалибровать | если ты уже подобрал удачный помол, укажи его здесь, чтобы конвертер учитывал эту настройку в следующих расчётах |
| `h-conv-use` | взять в заваривание | нажми эту кнопку, чтобы перенести результат в рецепт. в поле помола появится середина рассчитанного диапазона |

### ЖУРНАЛ (`log`, `detail`, `compare`)

| id | Зона | Текст |
|---|---|---|
| `h-log-filters` | лента чипов | здесь можно отобрать записи по кофе и способу приготовления |
| `h-log-compare` | сравнить | выбери две записи, чтобы сравнить приготовления и увидеть, чем они отличаются |
| `h-detail-repeat` | повторить | эта кнопка перенесёт параметры из записи в новое приготовление, чтобы ты мог повторить рецепт |
| `h-detail-stages` | секция стадии | здесь записано, как прошло приготовление, включая паузы. точкой отмечены действия без отсчёта времени |
| `h-detail-qr` | блок qr | в этом коде сохранены помол, дозировка, количество воды, температура и этапы приготовления |
| `h-compare-diff` | строки сравнения | более ярким текстом показаны параметры, которые отличаются в этих приготовлениях |

### НАСТРОЙКИ (`more`, `devices`, `device`)

| id | Зона | Текст |
|---|---|---|
| `h-more-grinders` | секция кофемолок | здесь можно добавить свои кофемолки и указать для каждой название и размер деления в микронах, чтобы конвертер мог пересчитывать помол |
| `h-more-transfer` | экспорт | сохрани архив со всеми данными, чтобы перенести их на другое устройство или сделать резервную копию. при импорте данные из архива заменят всё, что сейчас сохранено в приложении |
| `h-devices-new` | + новый девайс | добавь своё устройство для приготовления кофе и выбери его форму, материал и фильтр |
| `h-device-presets` | лента заготовок | выбери готовый вариант, чтобы не заполнять всё вручную. потом можно изменить любые параметры |
| `h-device-flow` | группа «поток» | от выбранного способа приготовления зависит, какие шаги появятся в таймере |

Про возраст и фазу обжарки подсказки нет намеренно: и то и другое подписано на
самой карточке пачки, и подсказка повторяла бы экран.

## 5. Из чего это собрано

| Файл | Что |
|---|---|
| `data/hints.ts` | реестр: id, экран, ключ строки, селектор зоны |
| `data/strings.ts` | 36 текстов + 8 подписей интерфейса, RU и EN |
| `db/schema.ts` | ключи `hints`, `hintsOn` в `SettingsValues` |
| `db/repo/settings.ts` | `markHint`, `resetHints`, `setHintsOn`, `useShownHints`, `useHintsOn` |
| `ui/hints/hint-view.ts` | чистая логика: очередь, границы зоны, сторона карточки |
| `ui/hints/HintLayer.tsx` | поиск зоны, замер, отрисовка; смонтирован в `App.tsx` |
| `ui/hints/hints.css` | неблокирующая рамка зоны, карточка, явные действия |
| `tests/unit/hint-view.test.ts` | проверки очереди и размещения карточки |

**Зона ищется селектором, а не ref'ом.** Половина зон уже помечена `data-testid`
ради e2e; заводить второй механизм разметки ради подсветки не за чем, а `ref`
пришлось бы прокидывать через компоненты, которые о подсказках знать не должны.
Там, где готового `data-testid` не было, экран несёт `data-hint="…"`.

**Опрос, а не `MutationObserver`.** Дешёвый `querySelector` по двум-трём
селекторам раз в 700 мс стоит меньше наблюдателя за всем деревом и не
срабатывает на каждый тик таймера.

### Добавить свою подсказку

1. Строка в `data/strings.ts` — обе таблицы, RU и EN, плюс счётчик ключей в
   `tests/unit/strings.test.ts` (он там намеренно жёсткий).
2. Запись в `HINTS` с новым id и селектором зоны.
3. Если готового якоря нет — `data-hint="…"` на нужный элемент экрана.

## 6. Проверки

`tests/e2e/onboarding.spec.ts` проверяет пустой первый запуск, обычное действие
подсвеченной кнопки, отсутствие продвижения по пустому месту и контраст
доступной навигации в обеих темах. Проверки цикла, экспорта и адаптивной вёрстки
остаются частью `npm run verify:journal`.

Визуальный проход младшей модели выполняется отдельно на production-сборке,
с чистыми данными и только по скриншотам. Это проверка понятности для агента,
не замена исследования с людьми.

## 7. Решения, принятые по ходу

| Вопрос | Решение |
|---|---|
| Первый запуск | встроенное объяснение и добавление первого кофе; тур Главного после появления пачки |
| Таймер | подсказок нет вовсе |
| Возраст обжарки | в подсказках не объясняем |
| Импорт архива без `hints` | подсказки покажутся заново, один раз |
| Закрытие | явное отключение глобально; использование контрола закрывает текущую подсказку |

Английские тексты — рабочий вариант, носителем не вычитаны.
