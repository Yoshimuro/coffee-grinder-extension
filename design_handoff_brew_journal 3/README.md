# Handoff: Brew Journal — local-first приложение для спешелти-кофе

## Что это
Прототип мобильного приложения: конвертер помола (из базы кофемолок → в свою), журнал заваривания с таймером и паузами, полка зерна (фото-first), конструктор девайсов с генеративным чертежом, двухшаговая оценка чашки (диагностика → цветное колесо вкусов ~100 дескрипторов RU/EN). Один пользователь, полностью офлайн, без аккаунтов/платежей/соцфич/BT/ИИ.

## Про файлы дизайна
Файлы в этом пакете — **дизайн-референсы на HTML** (интерактивный прототип), не production-код. Задача — **воссоздать** эти экраны и поведение в целевом стеке, а не переносить HTML как есть. `Brew Journal.dc.html` открывается в браузере: вся логика экранов в классе `Component` внизу файла, все данные/словари/формулы — в `data.js` (его МОЖНО переносить почти как есть — это чистый JS без UI).

## Fidelity: HIGH
Пиксельная точность: цвета, типографика, отступы, размеры — финальные. Копирайт финальный (RU + EN, мультиязычность заложена — см. `STR` в data.js).

## Рекомендуемый путь к APK
Цель: APK сейчас, PWA потом. Разумный вариант — **один веб-кодбейс + Capacitor**:
1. Приложение как local-first SPA (React/Preact/Svelte — любой), данные в IndexedDB (Dexie), никакого бэкенда.
2. **Capacitor** оборачивает в полноценный APK: доступ к камере (полка), файловой системе (экспорт/импорт JSON), keep-awake (таймер), локальные уведомления («оценка ждёт»), офлайн-распознавание речи (плагин `@capacitor-community/speech-recognition`; если недоступно — молча деградировать до клавиатуры).
3. Тот же кодбейс позже публикуется как PWA (manifest + service worker уже совместимы).
4. Логика конвертера из Chrome-плагина (134 кофемолки) — это уже JS: переносится в этот кодбейс напрямую, единый источник правды для плагина и приложения.
Альтернатива — нативный Kotlin/Compose: лучше keep-awake/уведомления/речь, но конвертер придётся портировать и PWA не переиспользуется.

## Жёсткие рамки (не проектировать вообще)
Local-first, ни одного сетевого запроса; без логина; без платежей; без соцфич; без умных весов/BT; без ИИ-чатов. Шаринг — только экспорт файла или QR рецепта (как «физическая передача»).

## Экраны (все в прототипе, навигация кликабельна)

### 1. Домашний — **финальный вариант C** (в прототипе переключатель A/B/C над рамкой; реализовать C)
- Строка действий: большая инверсная ЗАВАРИТЬ (60px) + квадратная кнопка ⇄ (конвертер); под ней ОЦЕНИТЬ ЧАШКУ (дегустация вне своих заварок).
- Карточка «оценка ждёт» над действиями (без анимаций!): название · когда · кнопка ОЦЕНИТЬ. Появляется при status=pending.
- Ниже — лента ЖУРНАЛ: 5 последних записей (дата · название · тех-строка параметров · оценка С N), тап → деталь.
- Пустой журнал → экран приглашает заварить, не объясняет функции.

### 2. Конвертер помола
- ОТКУДА: выпадающий пикер с поиском по **базе кофемолок** (в прототипе 24, в проде — база плагина, 134). КУДА: всегда **своя** кофемолка (из настроек; тап перебирает свои).
- Модель: value → µm (zero + step·value) → обратно в шаги своей. Диапазон ±12 µm — **диапазон и есть главный результат** (огромные цифры `3.2—4.6`, полоса-шкала с центром), центр — второстепенная строка.
- Техстрока: `30 кликов · 730 µm`, `разрешение 8.7 µm/шаг`.
- ОТКАЛИБРОВАТЬ: пользователь указывает настройку, реально давшую хороший результат (подсказка подтягивается из журнала — лучшая по сладости запись); хранится offset в шагах своей кофемолки, применяется ко всем будущим пересчётам, сбрасывается.
- ВЗЯТЬ В ЗАВАРИВАНИЕ — переносит центр в сетап.

### 3. Заваривание (сетап)
- КОФЕ: выбор с полки (тег формы: ЗЕРНО/МОЛОТЫЙ/ДРИП-ПАКЕТ) + кнопка «+ ЗЕРНО» (инлайн-добавление, после сохранения возврат сюда с выбранной пачкой).
- **Форма кофе определяет поля** (не метод): зерно → ПОМОЛ (текстовый ввод с клавиатуры + степперы ±0.1, подсказка диапазона из конвертера); молотый → без помола; дрип → без помола и без веса вообще (физически отсутствуют), «пакет = упаковка и воронка», девайс не выбирается.
- ТИП ЗАВАРИВАНИЯ: свои девайсы (мини-чертежи) + «+ ДЕВАЙС». Гибрид (Switch) → режим конкретного заваривания: ИММЕРСИЯ / ПРОЛИВ / СЕРЕДИНА (+ время открытия клапана степпером, «переменная рецепта»).
- ВЕС, ВОДА, ТЕМПЕРАТУРА, ПРОЛИВЫ (1–6, для пролива/гибрида-пролива/дрипа) — соотношение 1:N в шапке.
- СТАРТ → таймер; «ЗАПИСАТЬ БЕЗ ТАЙМЕРА» → рецепт уже пролит, вписать как есть (создаёт запись pending из плановых стадий).

### 4. Таймер (4 типа, работает одной рукой)
- Перколяция: СМАЧИВАНИЕ → ПРОЛИВ×N → ДРЕНАЖ; иммерсия: НАСТАИВАНИЕ → РАЗМЕШАТЬ → СЛИВ/ПРОДАВИТЬ; гибрид: + ОТКРЫТЬ КЛАПАН как отметка; дрип: проливы×N с настаиваниями.
- Огромный elapsed (74px), шкала стадий сегментами, текущая стадия капсом 29px, накопительная вода `95 г из 250`, отклонение от цели `− 0:12 / + 0:05`.
- **ПАУЗА** (кнопка над главной): закрывает текущую стадию, копит «стекание» как отдельную стадию с реальным временем; главная кнопка становится именем следующей стадии. В журнал пишутся **фактические** длительности всех стадий, включая паузы.
- Экран не гаснет (keep-awake). Ничего не спрашивает во время процесса.
- ГОТОВО → экран «Оценка позже»: ОЦЕНИТЬ СЕЙЧАС / ПОЗЖЕ (запись сохранена как pending; кофе раскрывается на остывании).

### 5. Оценка — два шага, не сворачивать в один
- **Шаг А. Диагностика** (серый, инженерный): 4 шкалы 0–10 тапом по ячейкам: КИСЛОТНОСТЬ, ГОРЕЧЬ, ТЕЛО, СЛАДОСТЬ. Карточка-вход в колесо: **цветная мини-версия колеса** + «ДЕСКРИПТОРЫ» — единственное цветное пятно экрана. Заметка + крупная кнопка ГОЛОСОМ (распознанные дескрипторы из словаря предлагаются тегами, не проставляются молча). Выбранные дескрипторы — теги с интенсивностью ●●○ (тап циклит 1–3), ×.
- **Шаг Б. Колесо** — по желанию, отдельный экран.
- Дегустация «вне журнала» (кофейня): тот же экран + необязательное поле «что за кофе»; запись в журнале «дегустация · без рецепта», фильтр ЧАШКИ.

### 6. Колесо вкусов — signature, единственное место цвета
- SVG, старт с 9 категорий, **проваливание из центра наружу**: тап по сектору → категория разворачивается на весь круг (подкатегории) → дескрипторы. Остановка валидна на любом уровне (кнопка «+ Фруктовое» в хлебных крошках).
- Центр круга = ВВЕРХ (имя уровня); хлебные крошки `ВСЁ / Фруктовое / Ягоды`; анимация — масштаб как «приближение» (in: scale .72→1, out: 1.36→1, ~320ms cubic-bezier(.22,.8,.24,1)), не смена экрана.
- Тап — только тап, **не свайп** (левый край iOS — системный «назад»).
- **Память**: дескрипторы, выбиравшиеся раньше, помечены белой точкой у внешнего края сектора — без счётчиков.
- Выбранные копятся внизу тегами с интенсивностью; несколько допустимо.
- Цвет: oklch, hue фиксирован на категорию (fruit 20, floral 330, sweet 85, nutty 55, spice 45, roast 30, green 150, ferment 310, other 250), chroma по категории (0.04–0.16), lightness 0.60–0.78 по индексу внутри уровня. Текст секторов #0D0D0B.
- **Юридически**: словарь и иерархия — свои (по мотивам общепринятой), геометрия/палитра/тексты SCA-WCR не воспроизводятся (CC BY-NC-ND). RU-локализация адаптивная (узнаваемые референсы: квас, кефир, топлёное молоко, курага).
- Полный словарь: `WHEEL` в data.js (9 категорий → 26 подкатегорий → ~100 дескрипторов, id + ru + en).

### 7. Полка
- Список в один столбец: карточка = квадратное фото слева (118px) + название/данные. Пачку узнают по пачке; вокруг фото тихая рамка (это единственное «чужое» цветное пятно кроме колеса).
- Свежесть: `5 дн · пик` (фазы: дегазация <4, пик 4–21, спад >21) + остаток (`172 г` / `осталось 3` для дрипа — в штуках!).
- Карточка пачки: фото **столбцом** (первое = лицо, порядок задаёт пользователь, минимум два снимка: лицо/шов с датой/оборот), открытие на весь экран в 1 тап; поля: дата обжарки, вес — только то, что участвует в расчётах; название необязательно. Никакого OCR.
- Добавление: СНЯТЬ ПАЧКУ / ВПИСАТЬ РУКАМИ — равноправны. Форма: ЗЕРНО/МОЛОТЫЙ/ДРИП (у дрипа — штуки в коробке вместо веса).

### 8. Девайсы — конструктор по признакам
- Признаки: поток (пролив/иммерсия/гибрид-клапан), дно (конус/плоское/корзина/цилиндр), стенка (рёбра/спираль/лепестки/гладкая), фильтр (бумага-конус/волна/диск/металл/ткань/встроенный), материал (керамика/стекло/пластик/металл), объём (3 ступени).
- **Чертёж-силуэт генерируется из признаков** (тонкий линейный разрез, без заливки): метод `devSvg()` в прототипе — конус/трапеция по дну, двойная стенка по материалу (толщина: керамика 5.5 > цилиндр-металл > стекло > пластик 0), текстуры стенки, штрихи фильтра, клапан кружком, капли перколяции. Перестраивается на глазах при выборе признаков + техподпись-строка и заметка о влиянии (лепестки → быстрее поток; керамику греть дольше).
- Признаки попадают в журнал и участвуют в сравнении.

### 9. Журнал
- Фильтры-теги: по зерну, режиму (ПРОЛИВ/ИММЕРСИЯ/ГИБРИД/ДРИП/ЧАШКИ), кнопка ЗАВАРИТЬ в шапке.
- СРАВНИТЬ: чекбокс-режим, выбрать 2 → таблица бок о бок, **отличающиеся значения белые+жирные, совпадающие приглушены** (#6E6E68). Строки: зерно, девайс, режим, помол, вес, вода, температура, время, клапан, 4 шкалы, дескрипторы, заметка.
- Деталь записи: параметры сеткой, стадии с водой и длительностями (включая паузы), диагностика строкой, дескрипторы тегами с интенсивностью, заметка, QR рецепта («передача — файлом или с экрана»), ПОВТОРИТЬ → сетап с этими параметрами.

### 10. Настройки
МОИ КОФЕМОЛКИ (добавить: имя + шаг µm, единица всегда клики; удалить с подтверждением «УДАЛИТЬ? ДА/✕», минимум одна) · МОИ ДЕВАЙСЫ → конструктор · ЯЗЫК RU/EN · ЭКСПОРТ БАЗЫ В ФАЙЛ (JSON) · ИМПОРТ · СПЕЦИФИКАЦИЯ. Подвал: `локально · офлайн · без аккаунта · v0.1`.

## Модель данных (см. сиды в data.js)
- **Grinder** (своя): {id, name, step µm/клик, zero µm, unit}. **GrinderDB**: то же + short; в проде — база плагина.
- **Bean**: {id, form: beans|ground|drip, name?, roaster?, roast: ISO, photos[], weight/left (г) | count/leftCount (шт) + dose для дрипа}.
- **Device**: {id, name, flow, bottom, wall, filter, material, vol} — enum-ключи из `TRAITS`.
- **Entry**: {id, date, time, bean|null, device|null, devName, mode: perc|imm|hybrid|drip|cup, grind|null, dose, water, temp, total сек, stages: [[key, duration сек, water г]], pours?, valveAt?, status: pending|done, diag {acid,bitter,body,balance 0..10}, desc: [[descriptorId, intensity 1..3]], note, title? (для cup)}.
- Стадии-ключи: bloom, pour, drain, steep, stir, press, valve (отметка, 0 сек), pause.
- Правила: сохранение заварки уменьшает остаток пачки (граммы или штуки); calibration offset хранится отдельно от журнала; «память колеса» = union дескрипторов всех done-записей.

## Поведение и платформа
- Android первым, iPhone заложен: явная кнопка ← везде где вложенность; без Material 3 (никаких FAB/switch); safe area сверху и снизу; проваливание колеса тапом, не жестом от края.
- Тон: плоские глаголы (`ЗАВАРИТЬ`, не «Давай заварим!»), единицы всегда рядом с цифрой, приложение не хвалит, пустые экраны приглашают, ошибки без извинений.
- Никаких очков/уровней/стриков/прогресса. «Тренажёр вкуса» = память колеса + повторяемость (прошлые слова о том же зерне), выводы делает человек.
- Локальное уведомление после заваривания → «оценка ждёт» (карточка на домашнем).

## Файлы пакета
- **`Brew Journal offline.html` — эталон для просмотра: один файл, открывается с диска двойным кликом, всё зашито внутрь.** Смотреть дизайн — здесь.
- `Brew Journal.dc.html` — исходник прототипа: шаблоны экранов + класс `Component` (вся логика: конвертация, стадии, таймер с паузами, колесо, чертёж девайса, сравнение). С диска напрямую не откроется (CORS) — для чтения кода, не для запуска.
- `data.js` — **переносимое ядро**: словарь колеса (WHEEL/DESC), строки RU/EN (STR), признаки девайсов (TRAITS), база кофемолок (GRINDER_DB), формулы конвертации, фазы свежести, сиды демо-данных.
- `image-slot.js`, `ios-frame.jsx`, `support.js` — обвязка прототипа (не переносить).
